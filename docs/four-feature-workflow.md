# 네 가지 제작 기능 통합 안내

이 확장은 검증이 끝난 입력만 받던 진입 경로, 상품별 단발 호출, 제한적인 이미지 입력, 무음 영상이라는 네 기능 공백을 대상으로 한다. 외부 게시나 무인 운영을 켜는 작업이 아니다.

## 기능별 입출력

| 기능 | 입력 | 출력 | 자동으로 하지 않는 것 |
| --- | --- | --- | --- |
| 상품 초안 | 상품 URL, 프로그램, 선택적 로컬 HTML/JSON/텍스트 | 원문 스냅샷, 후보, 누락 목록, 검토 이력, 정식 manifest | URL 방문, 사실/권리/제휴 소유 자동 승인 |
| 영속 작업 큐 | 정식 manifest, 상품별 선택 작업, 제공자 설정, 한도 | 호출 이력, 미검토 후보, 검토 결과, 새 manifest, 카드·릴스 | 불명 결과 재호출, 모델의 자기 승인, 외부 게시 |
| 이미지 준비 | 원본, 작업별 권리 진술, 명시적 변환 옵션 | 보존 원본, 호환 파생 이미지, 변환·해시·색상 관리 기록 | 금지 소재 편집, 임의 확대·크롭, 프로필만 삭제 |
| 자막·오디오 합성 | 검증된 무음 릴스, 대본/프레임 자막, 폰트, 제공된 음성/음악 | MP4, SRT/VTT, 원본/결과 해시, 길이·음량 검증 | TTS 서비스 호출, 음원 검색/다운로드, 사용권 추정 |

## 권장 순서

1. `draft-init`으로 한 상품의 부분 초안을 시작하고 `draft-ingest`로 원문을 추가한다. HTML 안의 script를 실행하지 않고 제한된 구조화 데이터만 후보로 추출한다.
2. `draft-report`에서 누락 항목을 확인한다. `draft-review`로 직접 확인한 정보를 명시하고 정확한 초안 SHA를 묶어 `draft-promote`한다. 초안 한 개는 한 상품이다. 여러 상품을 쓸 때는 각 항목의 근거를 보존한 정식 다상품 manifest를 준비한다.
3. 원본 이미지가 입력 계약에 맞지 않으면 `prepare-image`를 사용한다. 필요한 변환별 권리가 없으면 중단한다. `verify-image`로 보존 원본에서 파생 결과를 재현·검증한 뒤 정식 manifest의 asset 경로로 사용한다. 원본 폰트·이미지·음원 권한을 다른 권한으로 대체하지 않는다.
4. `workflow-plan`으로 변경 없는 계획을 확인하고 `workflow-init`으로 새 작업 디렉터리를 만든다. `workflow-run`은 선택된 제공자 호출만 실행하며, 기본 네트워크 미허용 상태를 유지한다. 작업이 비어 있으면 기존의 검증된 입력을 유지한 오프라인 카드/릴스 빌드도 가능하다.
5. 후보가 생기면 `workflow-status`를 확인한다. `workflow-review`는 정확한 후보 해시와 운영자의 명시적 판단을 요구한다. 모델이 생성한 `reviewed` 값으로 이를 대신할 수 없다. 실패/불명 상태는 `workflow-resolve`의 명시적 판단 절차를 따른다. 기존 build/reel lock을 자동으로 제거하지 않는다.
6. 완성된 무음 릴스에 `compose-reel`을 적용해 제공된 대본·자막·사용권이 확인된 로컬 오디오를 결합한다. `verify-composition`에 별도로 보관한 manifest SHA를 넣어 검증한다. 원래 무음 영상은 변경하지 않는다.

각 명령의 정확한 인수·JSON 계약은 [초안](drafts.md), [작업 큐](workflow.md), [이미지](image-preparation.md), [영상](reel-composition.md) 문서를 따른다. 입력 경로와 명시적 승인 필드를 추측해 채우지 않는다.

## 검증 의미

회귀 테스트와 실제 로컬 미디어 인코딩으로 소프트웨어 동작을 확인한다. 로컬 모의 HTTP 서버의 응답은 실제 모델 실행 결과가 아니며, 테스트용 판매 manifest는 실제 상품 가격·제휴 자격·이미지 권한의 증명이 아니다. 통합 테스트의 합성 음원은 수학적으로 생성한 신호이지 TTS나 인간 음성이 아니다.

기존 카드 생성과 무음 릴스 경로는 유지한다. 변환·자막·오디오처럼 새로 선택한 기능은 의도적으로 새로운 결과물을 만들므로 원래 이미지와 영상의 픽셀 동일성을 주장하지 않는다. 변환하지 않는 기존 경로의 회귀와 새 기능의 정확성은 별개로 검사한다.

실제 상품/모델 품질과 비용, Mac에서의 수치, 모든 입력에서의 성능 무회귀는 별도 실증이 필요하다. 구현 완료와 이 검증 항목의 완료를 혼동하지 않는다. 모든 검토용 결과의 `publish_ready`는 false이다.

## 검증 가능한 불변식과 짧은 증명

아래 성질은 유효한 입력, 정상 로컬 파일시스템, 동일 작업에 대한 배타 잠금, 테스트된 코드/라이브러리를 전제로 한다. 법적 권리의 진실성, 모델의 사실성 또는 악의적인 전체 파일 교체를 증명하지 않는다.

### 초안과 검토

추출 후보는 정식 manifest 필드와 별도로 저장되고, 추출 명령은 확인 플래그를 true로 바꾸지 않는다. 정식 출력은 정확한 초안 해시에 대한 명시적 검토와 기존 validate_manifest를 모두 거쳐야 작성된다. 따라서 추출만 수행한 상태에서는 미확인 필드가 검토 완료로 승격되지 않는다. 후보 가격은 JSON 부동소수점을 거부하고 정수 또는 정확한 10진 문자열만 수용하므로 binary float 반올림을 사실 가격으로 바꾸지 않는다.

### 누적 호출 한도

한도 L과 이미 예약된 양 R이 음이 아닌 정수이고, 새 요청 예약량 c에 대해 R+c≤L일 때만 잠금 안에서 R←R+c를 영속 기록한 뒤 요청한다. 초기 R=0이며, 귀납적으로 각 예약 후 0≤R≤L이다. 요청 수·출력 토큰 예약·전송 바이트 각각에 적용된다. 실패/429/불명 요청의 예약을 임의 환불하지 않으므로 중단 후 재개도 한도를 새로 시작하지 않는다. 제공자의 실제 금전 과금은 이 정수 예산과 별개이며, 외부 서버의 exactly-once 실행은 보장하지 않는다.

### 크기와 비율

원본 폭 w, 높이 h에 공통 유리수 배율 s=min(1,800/w,560/h)를 적용한다. 실제 정수 치수는 W=⌊ws+1/2⌋, H=⌊hs+1/2⌋이다. 따라서 확대하지 않고 출력 계약의 경계를 넘지 않으며, 공통 배율에 대한 각 축의 반올림 오차는 0.5픽셀 이하이다. 모든 입력 비율에서 정수 픽셀 비율이 수학적으로 완전히 같다고 주장하지 않는다. 한 축이 1픽셀도 되지 않는 극단적 비율은 거부한다. 원본 바이트는 별도 파일로 보존하고 재생성 검증에서 출력과 대조한다.

### 자막·오디오 시간축

자막은 유효한 정수 프레임 구간 [a,b)와 대본의 순서 있는 발췌로 제한한다. 0≤a<b≤N 및 구간 비중첩 검사를 통과해야 하며, 영상 시간축은 프레임 번호/fps의 유리수로 계산한다. 오디오 표본 수는 고정 표본률과 목표 길이에 맞춰 확인하며, pad/truncate는 명시적으로 선택한 정책에서만 수행한다. 인코더 성공 반환만 믿지 않고 실제 스트림·프레임/표본 길이·음량·파일 해시를 검사하고, 저장된 자막 프레임/오디오로 영상을 다시 만들어 검증한다. AAC 지연·정수 표본화 및 컨테이너 시간축 처리는 실제 29fps 시험을 포함해 검증한다. 음성의 의미나 청감 품질에 대한 수학적 증명은 아니다.
