# 검증 근거와 증명 범위

## 조건부 수학적 불변식

코드는 다음을 검증하며 테스트는 그 구현을 검사합니다. 테스트 통과를 AI 의미·미학의 수학적 증명이라고 부르지 않습니다.

1. **번호 대응:** 입력 n개에 대해 n∈[1,5]이고 i번째 ID=`format(i+1, '02d')`를 강제합니다. 따라서 서로 다른 위치의 ID는 서로 다르고 카드/캡션/links를 같은 순서의 리스트에서 생성하면 대응은 전단사입니다. 제품 교체의 진실성은 별도의 증거 검수 대상입니다.
2. **원본 링크 보존:** 출력 값은 입력 문자열의 직접 대입입니다. URL 파싱은 validation에만 사용하며 재직렬화하지 않습니다. 따라서 같은 Unicode 문자열을 UTF-8로 쓰고 읽었을 때 code point/UTF-8 bytes가 같습니다. JSON 자체의 quote/escape 표기와 URL 문자열 바이트는 구분합니다. 리디렉션 목적지/실적 인정은 증명하지 않습니다.
3. **원본 보존:** originals의 바이트 B는 입력 B를 그대로 씁니다. 해시 비교는 SHA-256 충돌 저항성 가정하에 변경을 탐지하며 테스트는 바이트 동등성도 확인합니다.
4. **무편집 배치:** RGB 단일 프레임 이미지 I(w,h)를 정수 좌표 (x,y)에 native paste합니다. 생성 이미지 C의 해당 영역에 대해 ∀i∈[0,w),j∈[0,h): C(x+i,y+j)=I(i,j)를 실제 픽셀 비교합니다. 입력 JPEG의 압축 바이트와 decoded RGB pixels는 별개의 보존 대상이며 둘 다 다룹니다.
5. **경계/충돌:** 모든 기록된 사각형 R=(l,t,r,b)는 0≤l<r≤1080, 0≤t<b≤1350입니다. 텍스트/장식은 이미지 영역과 분리하고 지정된 영역에 실제 측정값이 들어가지 않으면 실패합니다. 원본의 빈 배경까지 포함해 crop/resize하지 않습니다.
6. **결정성:** 같은 canonical 입력, 코드, font/asset bytes, Python/Pillow/fonttools 버전에서 알고리즘이 결정적이면 PNG/텍스트의 바이트가 같습니다. ZIP entry 순서·시간·권한·압축(STORED)을 고정하므로 ZIP 바이트도 같습니다. 다른 렌더 라이브러리/OS 빌드까지 비트 단위 동일하다고 가정하지 않습니다.
7. **캐시 무효화:** 지문 F=SHA256(canonical(입력/소스/asset/font/runtime hash map)). 하나가 바뀌면 충돌 저항성 가정하에 F가 달라지고 새 run 경로를 씁니다. 결과물 변경은 stage 해시 검증 실패로 드러납니다.
8. **검토 범위:** receipt는 정확한 ZIP digest와 F를 명시합니다. 다른 바이트의 ZIP은 같은 신뢰된 digest를 만족할 수 없다고 가정합니다. receipt 자체는 인증되지 않은 로컬 운영자 진술이며 전자서명/게시 권한이 아닙니다.

## 아직 증명/실측하지 않은 것

- 실제 상품 사진/색/로고/구성품과 현실의 일치, 사용권의 법적 유효성
- 최신 프로그램 조건, 운영자의 실제 채널·계정 승인, 제휴 링크 귀속/수익
- AI 조사·카피·이미지의 진실성, 미학, 의미 품질과 기존 대비 비회귀
- 사용자 Mac의 성능과 실제 운영 미디어의 처리량
- 외부 계정 게시 성공이나 실제 매출 성과

현재 저장소 시작점은 문서/설정뿐이므로 기존 코드의 동일 workload 성능 수치가 없습니다. measured baseline은 이번 구현의 관찰값일 뿐 속도 향상률이 아닙니다. 테스트 fixture는 명시된 합성 도형입니다. 사용자 승인 디자인 goldens를 별도로 얻기 전에는 자동 이미지 diff를 미학 보증으로 쓰지 않습니다.

## 위협 모델

로컬 입력은 실수 또는 비신뢰 데이터일 수 있습니다. strict schema, 크기 제한, HTTPS형식 검증(접속 없음), symlink/상위경로 차단, secret-safe 오류, PNG/JPEG 제한을 적용합니다. 출력은 원자적 파일 교체와 단일 writer lock으로 보호합니다. 임의 악성 로컬 사용자가 동시에 파일을 교체하는 환경, OS/font/image 라이브러리 취약점, 도구 밖 유출은 완전 방어 범위가 아닙니다. 변조 검사는 외부의 신뢰된 SHA-256과 함께 써야 전체 패키지 대체까지 인증할 수 있습니다.

## 최초 측정 기준선 (2026-10-21)

Linux, Python 3.12.14, Pillow 12.3.0, fonttools 4.61.1; 동일 합성 도형 3개 + cover 1개, native 600×420 assets / 1080×1350 cards. 3회 독립 cold build에서 ZIP 바이트가 모두 동일했습니다.

- Cold build 중앙값 0.6775초 (0.6269–0.7285초)
- 무결성 확인을 포함한 warm resume 중앙값 0.0500초 (0.0384–0.0567초)
- 벤치마크 프로세스 전체 high-water RSS 498,765,824 bytes (약 475.7 MiB). 단계별 증분 메모리가 아닙니다.
- ZIP 276,217 bytes; PNG 합계 228,279 bytes
- ZIP SHA-256: `780c9c1e42f1c220d3684e1089d033f1831e0e8096ea97efd52dad20e5c4af90`

[전체 원시 측정](baseline-2026-10-21.json). 같은 구현의 cold/warm 경로 측정이며 기존 AI 작업이나 다른 코드보다 빠르다는 비교가 아닙니다. 최초 full unittest 61개 통과, 별도 검토에서도 61개와 표적 회귀 확인 18개 통과. 시각 검수는 합성 예제의 레이아웃 확인에 한정합니다.
